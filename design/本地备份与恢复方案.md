# 咻咿待办 · 本地备份与恢复方案

## 目标与范围

用户可以手动将本机数据保存成一个文件，并在重装或更换手机后从该文件恢复。无需账号或网络服务；保存位置由 Android 文件选择器决定，可以是手机目录，也可以是用户选择的文件提供方。本功能不自动上传，也不做定期备份。

备份包含：普通待办、定时任务、已完成任务、回收站中的任务、任务的备注/分类/优先级/创建与删除时间、截止或执行时间、多个提醒时间，以及日期选择方式、精准提醒开关、提醒声音选择。使用自定义提示音时，音频文件一并打包。一次性测试提醒的记录、当前“稍后 10 分钟”状态和系统通知历史不备份。

通知权限、精准闹钟的系统授权、荣耀后台管理等属于手机系统设置，不能由备份恢复。恢复后需在新手机的“提醒状态检查”中核对。

## 入口与界面

在“设置”首页增加“本地备份与恢复”入口，沿用现有图标、标题、状态和右箭头卡片样式。进入后显示两张操作卡片：

| 操作 | 文案与流程 |
| --- | --- |
| 导出备份 | 说明“将待办、定时任务、回收站、应用设置和自定义提示音保存为一个文件”；点击后由系统选择保存位置，默认文件名为 `咻咿待办-YYYYMMDD-HHMM.xybak`；完成后显示文件名和任务数量 |
| 从备份恢复 | 说明“恢复会替换当前应用内的数据”；先由系统选文件，再显示备份时间、待办数、定时任务数、回收站数；用户点击“替换并恢复”后才写入 |

恢复确认弹窗使用当前应用的白色圆角卡片、墨紫标题和糖果紫主按钮，明确显示“当前数据将被替换。建议先导出当前数据”。取消后不做任何改动。文件格式错误、版本过新、音频损坏或空间不足时，显示具体错误，当前数据保持不变。

## 文件格式

使用单个 ZIP 容器，扩展名 `.xybak`，内部仅有 `backup.json` 和可选的 `sound/<随机文件名>`。文件名不是安全依据；导入时要检查内容。

`backup.json` 包含 `format: "xiuyi-backup"`、`schemaVersion: 1`、`exportedAt`、`settings`、`tasks`、可选的 `customSound`。每个任务记录现有 `TaskStore.Task` 的持久字段：`id`、`title`、`note`、`category`、`priority`、`dueAt`、`reminderTimes`、`repeatDays`、`timed`、`paused`、`done`、`deleted`、`deletedAt`、`createdAt`。时间均为 Unix 毫秒；`remindAt` 可由 `reminderTimes` 算出，`snoozeAt` 恢复为 0。保留任务 ID，避免同一份备份恢复后任务引用变化。

设置只保存用户选择：日期选择方式、精准提醒开关、提醒声音模式和自定义音频名称。自定义音频在恢复时复制到应用私有目录，再生成本机可用的内容 URI；不能直接复用旧手机的 URI。内置和系统提示音不需要打包。

备份文件可能包含私人待办内容和录入的音频，文件本身不加密。导出页应提示用户妥善保管，不在界面中暗示它受密码保护。

## 导出与恢复流程

1. 导出：从 SQLite 读取一致的数据快照，读取设置与自定义音频，先在应用缓存目录写完整备份；成功后使用 Android `ACTION_CREATE_DOCUMENT` 让用户选择目标并复制。复制失败时删除临时文件，提示重试，不显示“备份成功”。系统文件选择器只授予用户选定文件的访问权，无需申请整个存储空间的权限。[Android 文件访问文档](https://developer.android.com/training/data-storage/shared/documents-files)
2. 预览：使用 `ACTION_OPEN_DOCUMENT` 选文件，流式读取到临时文件；校验 ZIP 结构、格式标识、版本、任务字段、重复 ID、时间与提醒关系、音频可读性，并限制文件大小和解压后总大小，防止损坏文件或压缩炸弹。未通过校验时不触碰数据库与设置。
3. 恢复：确认后，在一个 SQLite 事务中替换 `tasks` 表数据；保留备份 ID，恢复设置和自定义音频，再取消旧任务闹钟，按恢复后的任务逐条调用现有 `ReminderScheduler.update()`。已过期的提醒不补发；未完成的定时任务按当前 `advanceTimed()` 规则推进到下一次执行。任何写入失败都要明确提示，不能报告成功。
4. 完成：刷新首页、定时任务和回收站数量，显示“已恢复 N 项”；引导用户打开“提醒状态检查”，检查通知权限、精准提醒和后台电池管理。Android 闹钟依赖系统调度，数据文件本身不保存已安排的系统闹钟。[Android 闹钟文档](https://developer.android.com/develop/background-work/services/alarms)

实现时应避免数据库事务与设置文件更新之间出现“任务已替换、设置未恢复”的半成功状态：先准备并校验所有导入数据和音频，只有全部可写时才提交；如果提交后重新安排闹钟失败，应保留已恢复数据并明确提示用户在检查页重试安排。备份导入不与当前数据合并，避免重复任务与提醒冲突。

## 验收场景

1. 创建普通待办、多个提醒、定时任务并删除一项后导出；清空应用数据再恢复，列表、回收站、时间、分类和设置与备份一致。
2. 自定义 MP3 提示音随备份恢复后可以试听并用于新提醒。
3. 恢复前取消确认、选择错误文件、损坏文件或新版本文件，当前数据及提醒保持不变。
4. 恢复含过期提醒和定时任务的备份，不补发旧提醒；未来提醒重新安排，定时任务推进到下一次。
5. 无网络、锁屏后再次打开应用，已恢复的本地数据仍存在；系统权限未授权时，检查页明确提示。
