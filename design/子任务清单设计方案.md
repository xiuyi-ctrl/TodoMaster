# 咻咿待办 · 子任务清单设计方案

## 目标与范围

在“我的待办”中，把一项任务拆成可单独勾选的步骤。例如主任务“完成项目方案”下有“收集资料、写初稿、检查内容、提交方案”。子任务帮助记录进度，不单独出现在首页任务总数中。

首轮只为普通待办添加子任务。定时任务涉及每次执行后子任务是否重置，暂不混入本轮；现有定时提醒、优先级与分类规则不变。子任务只有**标题、完成状态和创建顺序**，截止时间与提醒仍设置在主任务上。

## 页面与样式

沿用奶油背景、白色圆角分区、墨紫文字和糖果紫选中态，参照 [移动端界面视觉规范](移动端界面视觉规范.md)。

| 位置 | 设计 |
| --- | --- |
| 新建／编辑待办 | 在“备注”后增加“子任务清单”分区。每行是圆角浅底输入项，左侧勾选框、中央标题、右侧删除图标；末尾为“＋ 添加子任务”。新建时先在表单内编辑，点击“保存待办”一起保存。 |
| 首页任务卡片 | 有子任务时，在标签下显示“已完成 2/4”与细紫色进度条；可附一条下一项未完成子任务的标题。无子任务时卡片保持现状。点击卡片进入编辑页查看完整清单。 |
| 已完成主任务 | 仍显示原子任务进度；主任务标题沿用已完成样式。再次取消主任务完成状态，子任务勾选状态保持原样。 |
| 空清单 | 显示“把这件事拆成小步骤吧”，提供添加入口，不展示 0/0 进度。 |

输入框与按钮跟随屏宽伸缩。长标题最多在首页显示一行并省略，在编辑页可完整查看；系统大字体下行高随内容增长，底部保存按钮不遮挡子任务列表。勾选沿用现有薄荷绿色完成动效，不为进度条增加持续动画。

## 交互规则

1. 点击“添加子任务”生成空输入行并聚焦。空白行不能保存；用户可以删除空行或填写标题后保存主任务。
2. 子任务按添加顺序显示，支持改名、勾选和删除；本轮不做拖拽排序或子任务嵌套。
3. 勾选子任务只改变该行与进度 `已完成数/总数`，**不会自动完成主任务**。主任务的勾选、通知快捷完成仍按原有操作执行，不会强制改写子任务状态。
4. 主任务移入回收站时，子任务随主任务一起隐藏且不再出现在组件中；恢复主任务时原有子任务与进度一同恢复。彻底删除主任务时一并删除子任务。
5. 首页“未完成/已完成”统计和搜索状态筛选只统计主任务。搜索标题仍只搜索主任务标题，避免一个子任务使同一主任务重复出现在结果里。
6. 桌面小组件继续显示主任务；宽组件可在任务标题旁以小字显示 `2/4`，不在有限空间内展开所有子任务。

## 数据与兼容

新增 `subtasks` 表：`id`、`task_id`、`title`、`done`、`sort_index`、`created_at`。`task_id` 指向现有 `tasks.id`；按 `sort_index, id` 排序。数据库从当前版本升级时创建新表，已有任务默认没有子任务。对子任务的增删改和主任务保存使用同一个数据库事务，避免只保存了部分清单。

本地备份文件需升级格式，保存每项主任务的子任务列表。新版本仍能读取旧备份（旧备份恢复后子任务为空）；旧版本应用不能恢复含子任务的新备份，应显示版本不支持。恢复前预览和确认替换的流程保持不变。

## 验收场景

1. 新建待办并添加四个子任务；完成两项后首页显示 `2/4`，主任务仍未完成。
2. 修改子任务标题、删除一项、取消勾选一项后，重新打开应用顺序与状态正确。
3. 完成主任务、通过通知快捷完成主任务，再取消完成时，子任务原状态均保留。
4. 删除主任务并从回收站恢复，子任务完整；彻底删除后不残留孤立子任务。
5. 导出并恢复备份后，子任务数量、顺序和完成状态一致；旧备份可正常恢复。
6. 窄屏和系统大字体下，输入框、删除按钮、进度文字不重叠。
